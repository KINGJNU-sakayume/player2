# 노트 쓰기

ARC Music의 노트는 손으로 쓴 글이다. 사용자가 디스코그래피를 순서대로 훑으며 읽는 글이므로, 한 장의 앨범을
**그 아티스트의 경력 안에 놓고** 읽게 하는 것이 목표다. 요청받은 대상에만 쓰고, 근거 없는 내용으로 빈자리를
채우지 않는다.

## 0. 먼저 확인할 것

- 기존 노트: `src/editorial/notes/{artists,albums,songs}/*.md`. 이미 있으면 새 파일을 만들지 말고 그 파일을 고친다.
  사용자가 다시 쓰라고 하지 않는 한 기존 문장은 바꾸지 않는다(추가·보강은 가능, `updated` 날짜 갱신).
- 앨범·곡 노트의 `artist`는 `notes/artists/` 파일 이름(키)이어야 한다. 아티스트 노트가 없으면 아티스트 노트도
  함께 쓰고, 그렇게 했다고 사용자에게 알린다.
- 같은 아티스트의 다른 노트를 읽고 앞뒤 내용과 어긋나지 않게 한다(예: 전작 노트에서 한 말과 모순되지 않게).

## 1. 대상과 Spotify ID 확인

- 노트는 Spotify ID로 먼저 매칭되고, 없으면 제목과 아티스트 이름으로 매칭된다(`src/editorial/lookup.ts`).
- 사용자가 준 `open.spotify.com/album/<ID>` / `track/<ID>` / `artist/<ID>` 링크의 22자 ID를 쓴다. 링크가 없으면
  웹 검색으로 찾는다. 확실하지 않은 ID는 넣지 말고 제목 fallback에 맡긴다.
- 한 릴리스에 ID가 여러 개인 경우가 많다(디럭스판, 지역판, 싱글 수록판). 아는 것은 모두 넣는다.
- `titles` / `names`에는 Spotify가 보여줄 수 있는 모든 표기를 넣는다: 원어, 로마자, 영어, 한국어
  (`[感電, Kanden]`, `[Kenshi Yonezu, 米津玄師, 요네즈 켄시]`). 앨범에는 `releaseYear`를 넣는다.

## 2. 조사

WebSearch / WebFetch로 확인한 사실만 쓴다. 조사할 것:

- 발매일, 레이블, 프로듀서·편곡·참여 아티스트, 수록곡과 선공개 싱글, 타이업(드라마·애니메이션·광고)
- 아티스트 인터뷰, 라이너 노트, 제작 과정에 대한 본인의 말
- **디스코그래피 속 위치**: 직전·직후 릴리스, 그 사이에 바뀐 것(사운드, 협업자, 레이블, 개인사), 반응과 성과
- 의견이 갈리는 부분은 출처를 확인해 "~라는 평이 있다"처럼 쓰지 말고, 근거를 들어 직접 판단하거나 뺀다.

참고한 자료는 `sources`에 남긴다(URL 또는 "잡지명, 호, 연도" 같은 표기). 확인하지 못한 사실(차트 순위,
판매량, 날짜)은 쓰지 않는다.

## 3. 쓰기

### 공통 문체

- 한국어 평론체, **'~다'로 끝나는 평서문**. 1인칭("나는", "필자는")은 쓰지 않는다.
- 주장에는 구체적인 근거를 붙인다: 곡 제목, 구간(인트로·브리지·마지막 후렴), 악기와 질감, 가사의 이미지, 트랙 순서.
- 상투어·홍보 문구 금지: "명반", "전설적인", "귀를 사로잡는", "역대급", "완성도 높은" 같은 말 대신 무엇이
  어떻게 좋은지 쓴다. 과장된 수사, 영어 단어 남용도 피한다.
- 앨범·곡 제목은 『앨범』, '곡' 표기를 쓴다. 고유명사는 처음 나올 때 원어를 괄호로 병기할 수 있다.
- 가사 인용은 분석에 꼭 필요한 짧은 구절(몇 단어)만. 가사 전체나 여러 줄을 옮기지 않는다.
- 점수·별점은 쓰지 않는다.

### 앨범 — 평론가형 리뷰

`short`(페이지에 보이는 프리뷰): 2–3줄, 약 80–130자. 이 앨범을 한 문장으로 규정하는 핵심 주장.

본문(`full`): 약 1,800–3,500자. 아래 흐름을 기본으로 하되, 앨범에 맞게 줄이거나 합친다. `##` 소제목은 긴 리뷰에서만
쓰고 2–4개 정도로 둔다(짧은 리뷰는 소제목 없이 문단만).

1. **리드**(소제목 없음): 이 앨범이 무엇을 하려 했고 실제로 무엇을 해냈는지.
2. **배경**: 발매 시점, 아티스트 경력에서의 위치, 전작에서 무엇이 바뀌었는지.
3. **사운드와 구성**: 프로덕션, 편곡, 시퀀싱(곡 순서가 만드는 흐름), 앨범을 관통하는 모티프.
4. **트랙 읽기**: 앨범의 성격을 보여주는 2–4곡을 구체적으로. 모든 곡을 나열하지 않는다.
5. **가사와 주제**: 반복되는 이미지와 화자, 앨범이 붙드는 질문.
6. **디스코그래피 속에서**(마지막): 이 앨범이 남긴 것, 다음 작품으로 무엇이 이어지는지, 함께 들을 앨범.
   평가는 여기서 분명하게 하되 점수 없이 문장으로.

### 아티스트 — Editorial Note

- `origin`: `도시, 나라 · 역할` 형식의 한 줄(예: `Tokushima, Japan · singer-songwriter / producer / illustrator`).
- `short`: 2–3줄, 이 음악가를 듣는 관점.
- 본문: 경력을 **시기(era)** 로 나눠 디스코그래피의 흐름을 보여준다. 시기마다 대표 앨범과 무엇이 달라졌는지.
  끝에 "처음 듣는다면" 들어갈 앨범을 제안할 수 있다. 소제목(`## 초기 (2012–2015)` 등)을 써도 된다.
- `eras`(선택): 본문의 시기 구분을 frontmatter에도 적으면 Artist 페이지의 디스코그래피 타임라인에 시기 표시가 붙는다.
  한 줄에 하나, `연도–연도 · 짧은 이름` 형식으로 쓴다. 진행 중인 시기는 끝 연도를 비우고(`2018– · …`), 한 해짜리는
  연도 하나만 쓴다. 이름은 10자 안팎으로 짧게, 본문과 같은 구분을 쓴다. 근거가 분명한 전환점(데뷔, 활동명 변경,
  레이블 이적, 결정적인 히트)만 시기로 나눈다.

  ```yaml
  eras:
    - 2009–2011 · 하치(ハチ), 보컬로이드 프로듀서
    - 2012–2017 · 『diorama』부터 직접 노래하기
    - 2018– · 'Lemon' 이후
  ```

### 곡 — Listening Note (곡 하나에 노트 하나)

- `short`: 1–2줄, 약 60–100자. 리뷰가 아니라 **무엇을 들어보라는 신호**("…를 따라 들어보면 좋다").
- 본문: 2–4문단. 들을 포인트(구조, 편곡, 목소리), 곡의 배경, 가사 해석.
- 곡 노트는 큐레이션 번역도 담는다(`translate-lyrics` 스킬). 노트에 다음이 있으면 **그대로 보존한다**:
  - frontmatter의 `translation:` 블록 (들여쓴 하위 필드 전부)
  - 본문 끝의 `## 번역에 대하여` 섹션 (예약된 제목이다. 감상 본문에 같은 제목을 쓰지 않는다)
  - 같은 이름의 `<key>.translation.json` 파일
  감상 본문은 `## 번역에 대하여` **위에** 쓴다. 화자·청자 해석이 번역 브리프와 어긋나지 않게 한다.
- 번역만 있는 곡 노트(`short`와 감상 본문이 없음)에 감상 노트를 더할 때는 `short`와 본문을 추가하고,
  번역 블록과 섹션은 건드리지 않는다. 곡 하나에 노트 파일을 둘 만들지 않는다.

## 4. 파일 형식

파일 이름이 키다: `src/editorial/notes/albums/stray-sheep.md` → `stray-sheep`(소문자, 하이픈).
frontmatter는 `src/editorial/frontmatter.ts`가 읽는 작은 YAML 부분집합이다: `키: 값`, `[a, b]` 목록,
`- 항목` 블록 목록, `키: >` 다음 들여쓴 줄(한 줄로 합쳐짐), 그리고 곡 노트의 `translation:` 같은 들여쓴 하위 블록.
쉼표가 든 목록 항목은 `"Tyler, The Creator"`처럼 따옴표로 감싼다.

```markdown
---
artist: kenshi-yonezu
albumIds: [052EiTRYh35MuDVJN9Emdh, 5XuZE4dvsiYEvRndrllt1t]
titles: [STRAY SHEEP]
releaseYear: 2020
written: 2026-10-02
sources:
  - https://example.com/interview
  - "Rockin'on Japan, 2020년 9월호"
short: >
  프리뷰 2–3줄.
---

리드 문단.

## 배경

…
```

| 종류 | 필수 | 선택 |
| --- | --- | --- |
| artists | `artistIds`, `names`, `short` | `origin`, `eras`, `written`, `updated`, `sources` |
| albums | `artist`, `titles`, `short` | `albumIds`, `releaseYear`, `written`, `updated`, `sources` |
| songs | `artist`, `titles`, `short`(번역 블록이 있으면 선택) | `trackIds`, `written`, `updated`, `sources`, `translation` |

본문은 문단(빈 줄로 구분), `##`/`###` 소제목, `- ` 목록, `> ` 인용, `**굵게**`, `*기울임*`,
`[텍스트](https://…)`만 렌더된다(`src/components/NoteBody.tsx`). 날짜는 `YYYY-MM-DD`.

## 5. 확인하고 커밋

1. `npm run check`: frontmatter 오류, 없는 아티스트 키, 중복 키, 그리고 곡 노트의 `translation:` 블록 ↔
   `.translation.json` ↔ `## 번역에 대하여` 짝이 맞지 않는 경우를 잡는다.
2. 미리보기 카탈로그(`/?preview`)에 있는 아티스트면 `npm run dev`로 페이지와 드로어를 확인한다.
3. 커밋 메시지 예: `notes: add STRAY SHEEP review`. 사용자에게 무엇을 근거로 썼는지(주요 출처)와
   확인하지 못해 뺀 내용을 짧게 알린다.
